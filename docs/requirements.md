# Requirements

Purpose: the fixed list of what Network Doctor must do. Each requirement has one test in `test-cases.md`.
Owner: Rafiq. Version 0.21.3. Date: 2026-11-23. The history of each version is in CHANGELOG.md.

Form: each requirement is one "shall" sentence that can be tested. A new idea is agreed first and then added here.

## Ground rules

- ND-01 The tool shall only read and report in stage 1; it shall not change any setting, driver, device or program. `install`, `uninstall` and `schedule` are not stage 1: they change only the program's own files, icons and jobs for the person who runs them (ND-274). (Amended 2026-11-20: Mac and Linux setup lives in the program itself.)
- ND-02 The tool shall run with no install, as a single executable per system (Windows, Mac, Linux, ARM Linux), also offered as a zip with a one-page guide.
- ND-03 The tool shall work offline except for the speed test and internet checks.
- ND-04 The tool shall keep all saved data on the local machine and shall send nothing anywhere unless the user turns it on.
- ND-05 All text shown to people shall be plain English at a 6th to 8th grade level.

## Checks

- ND-10 Diagnose: the tool shall detect whether the active connection is wired or Wi-Fi.
- ND-11 Diagnose: the tool shall measure speed and delay to the router and to the internet, and packet loss.
- ND-12 Diagnose: the tool shall name the most likely cause (this computer, cable or signal, router, or provider) and what to check first.
- ND-20 Bandwidth: the tool shall list the programs using the connection, ranked, with upload and download.
- ND-21 Bandwidth: the tool shall recommend which activities could be paused, and shall not stop any.
- ND-30 Drops: the tool shall read the last seven days of connection history and report the number of drops, the time of each and the length.
- ND-31 Drops: the tool shall point out patterns (time of day, power-saving, driver).
- ND-40 Link health, wired: the tool shall report link speed, duplex and error counts.
- ND-41 Link health, Wi-Fi: the tool shall report signal strength, band, channel and nearby networks on the same channel, with advice.
- ND-50 Devices: the tool shall list devices on the network with name, maker, address and hardware address, and flag any not marked known.
- ND-51 Devices: the tool shall never guess, store or log a router password.
- ND-60 Settings: the tool shall review DNS, adapter power-saving, VPN, proxies, adapter and driver version and configuration errors, and explain each finding and the effect of changing it.

## Modes

- ND-70 Reactive: the user shall be able to run a full check on demand.
- ND-71 Scheduled: the user shall be able to turn on a weekly check (default Monday 0900) that records speed, delay, date, time and subscribed speed to a spreadsheet file.
- ND-72 Scheduled: if download stays under half the subscribed speed for three consecutive weekly checks, the tool shall prepare a complaint email as a draft and shall never send it.
- ND-73 Proactive: the tool shall notify the user when the link drops, when speed stays below plan, or when a new unknown device appears.
- ND-74 Proactive: each alert type shall be switchable, shall honor quiet hours, and shall give one alert per outage.
- ND-75 Proactive: alerts shall go only where the user chooses; by default nowhere outside the machine.

## Interfaces

- ND-80 The tool shall have a command-line mode with no screen, JSON output and clear exit codes, for servers.
- ND-81 The tool shall serve a local web page for people and phones, reachable only from the local machine or networks the user allows.

## Stage 2 (apply with approval)

- ND-90 The tool shall apply a fix only after the user approves that single fix.
- ND-91 Before applying, the tool shall show the before and after values.
- ND-92 The tool shall save the old value and undo the change with one action.
- ND-93 The tool shall write every applied change to a log.
- ND-94 The tool shall request administrator rights only at the moment of approval.
- ND-95 The tool shall never apply driver changes, security-protection changes, or any change that could cut off the connection in use.
- ND-96 On an unattended server, apply shall be off by default and switchable only per machine by the user.

## Installer (Windows)

- ND-110 A Windows installer (`setup.exe`, offered in a zip with the guide) shall install Network Doctor without relying on any program, setting or file already on the computer.
- ND-111 The installer shall always install the on-demand check (reactive), and the person shall not be able to clear it.
- ND-112 The installer shall ask whether to add the weekly check (scheduled) and the alerts (proactive), each with a plain sentence saying what it does, and shall install only what is chosen.
- ND-113 Choosing neither, either one or both shall install exactly the on-demand check plus the chosen parts and nothing else.
- ND-114 The installer shall also run with no window, with switches that carry the same choices, for IT.
- ND-115 The installer shall put the program in Program Files, add an entry to Apps and features, and ask for administrator rights once.
- ND-116 An installed copy on Windows shall save its results, known devices and alerts in ProgramData; an unzipped copy, and an installed copy on Mac or Linux (ND-294), shall keep saving per person. (Amended 2026-11-20: scoped to Windows, since Mac and Linux installs are per person.)
- ND-117 The weekly check shall be a weekly task, and the alerts a task that starts when someone logs on and shows alerts on their screen; neither shall exist unless chosen.
- ND-118 The uninstaller (in Apps and features, in the program folder, and with a silent switch) shall undo exactly what the install did and, silent or not, shall delete the whole results folder (`ProgramData\NetworkDoctor`: saved results, the alert log, the known-devices list, the device choices, the settings and every other file the program wrote there) without asking whether to keep it, so a new install on that computer starts fresh; first it shall put back every fix still applied (ND-316), and when one cannot be put back it keeps only the undo notes as ND-316 says. Only `/KEEPRESULTS` shall keep that folder: given bare or with any value other than empty or `0` (`/KEEPRESULTS`, `=1`, `=yes`, `=true`), also when `/DELETERESULTS=1` is given; `/KEEPRESULTS=0` or `/KEEPRESULTS=` deletes. The old `/DELETERESULTS=1` shall still be accepted and only repeat the default. Inno Setup's own question, whether to remove Network Doctor, may stay. (Amended 2026-11-23: it asked whether to keep the saved results and kept them by default, so a new install showed old results. Amended again 2026-11-23: fixes are put back first, and any value of `/KEEPRESULTS` but empty or `0` keeps, since `/KEEPRESULTS` alone or `=yes` used to delete.)
- ND-119 The installer and uninstaller shall send nothing off the computer, except that the installer may fetch Ookla's own Speedtest tool from Ookla when the person asks for it (ND-210).
- ND-120 The installer shall be tested for all four choices, install then uninstall, on a Windows computer that has none of the developer's setup.

## Phone sharing, first-run helper, alerts file, Mac and Linux

- ND-130 A `share` command shall find this computer's address on the real network adapter (not a VPN), start the web page for that one network only, and print the address.
- ND-131 `share` shall also print a code on the screen that a phone camera can scan to open that address.
- ND-132 `share` shall wait for the first request from another device in the allowed range and say when it arrives; if none arrives within a minute it shall give plain advice from read-only facts (the Windows allow box, a public network, a VPN, a guest network).
- ND-133 `share` shall allow only the adapter's own network, and shall never change a firewall rule or any other setting.
- ND-134 If no network address can be found, `share` shall say so in plain words and shall not start.
- ND-140 A `setup` command (the first-run helper) shall ask for the plan speed and a name, show the devices found and ask which are the person's, and offer the weekly check, the alerts file and the phone page, one yes or no each.
- ND-141 The helper shall start by itself only when a person at a keyboard runs `netdoctor` with no command and no settings file exists; never for `check`, `weekly`, `watch`, `serve`, `open`, `install`, `uninstall`, `schedule`, JSON, the no-window build, the Mac app or a Linux launcher, or input that is not a keyboard. (Amended 2026-11-20: the Mac and Linux setup and icon routes added.)
- ND-142 Each offer shall say in plain words what it does, and each answer shall default to no.
- ND-143 The helper shall change nothing until the person says yes, and shall save only the tool's own settings and lists.
- ND-150 One command (`config alerts-file on` or `off`) shall switch the alerts file on or off without changing the other places alerts go.
- ND-151 When the alerts file is on, each alert shall be one line of time, kind and message, in a format written in the guide; when it is off nothing shall be written.
- ND-152 The alerts file shall be saved in the same folder as the tool's other results.
- ND-160 On Linux the tool shall read, without changing anything: the adapter (wired or Wi-Fi, link speed, duplex, errors, gateway, address), Wi-Fi signal, band and channel, line use and busiest programs, seven days of connection history, devices, and the six settings areas.
- ND-161 Where Linux cannot give a fact without administrator rights, the tool shall say so in plain words and shall not guess.
- ND-162 The reading of the system's own text on Linux shall be tested on sample text on every system the tests run on.
- ND-163 Every command the Linux and Mac readers run shall be read-only, checked by a test.
- ND-164 On GitHub's real Linux and Mac machines, a run of the built program shall read the adapter and say which kind it is.
- ND-170 On Mac the tool shall read the same facts as ND-160, without changing anything.
- ND-171 Where Mac cannot give a fact without administrator rights, the tool shall say so and not guess.
- ND-172 The reading of the system's own text on Mac shall be tested on sample text on every system the tests run on.
- ND-180 When the speed server refuses a test ("too many requests"), the tool shall report the speed as not measured, never as 0, say so in plain words with how long to wait, and carry both facts in its JSON.
- ND-181 After a refusal the tool shall not ask the speed server again until the wait is over, and shall remember the wait between runs.
- ND-182 The weekly check shall not save a row, and so never start a complaint draft, when the speed was not measured.
- ND-183 The default speed test shall use four connections or fewer and run three seconds or less, to stay light on the public server.
- ND-184 A speed measured less than ten minutes ago shall be reused instead of measuring again, with a plain note of how old it is, and the last measured speed shall be kept between runs. A speed that was not measured shall never be saved.

## Release

- ND-100 Each release shall include checksums and a signature.
- ND-101 Automated tests shall run on Windows and Linux for every change, and on a Mac in `parity-mac.yml`, started by hand (ND-313). (Amended 2026-11-20: the Mac run was cut from every change on 2026-11-20 and comes back by hand.)

- ND-206 The saved last speed shall remember which tool measured it.
- ND-207 The installer's choices file (`choices.json`, beside the program) shall say which parts the person chose (`core`, `scheduled`, `proactive`, `ookla`); a missing or damaged file says nothing.
- ND-208 Turning the weekly check on or off by hand shall keep the choices file in step, only when the installer wrote one.
- ND-209 The installer shall write the choices file from the parts selected, remove the task of any part not chosen (so running it again repairs the machine to match the choices), and the uninstaller shall remove the file and the `ookla` folder.
- ND-210 The installer shall offer Ookla's tool on its own page: unchecked by default, never in a silent install, the person's own license tick required, the file fetched only from Ookla over https and checked against a fixed SHA-256, and the license switches given to the tool only after that tick.
- ND-211 The program version shall be 0.4.0 in the program and in the installer file name.
- ND-212 The check shall name the fixes that fit what it found, in `fixes`: `name-cache` when web names cannot be looked up, `proxy` when a web proxy is turned on, and `power-saving` when the adapter's power saving can be read, is on, and a drop was seen in the past week; the list the check then gives is cut to the fixes the program can offer (ND-213). It shall never name any other fix, and names none when nothing fits. It shall change nothing.
- ND-213 For each name in `fixes`, the check shall also give an offer in `fix_offers`: the fix's plain title, the setting now, what it becomes, and whether Windows asks for administrator rights. Reading these changes nothing. A fix the program would refuse today, such as power saving (until a measured test shows it never drops the link in use), is left out of both `fixes` and `fix_offers`, so a button is never shown for a fix that cannot work.
- ND-214 With `--json`, `fix apply NAME`, `fix apply NAME --yes`, `fix undo NAME` and `fix list` shall print one JSON line (`ok`, `name`, `title`, `before`, `after`, `needs_admin`, `applied`, `undone`, and `error` in plain words when a fix is refused or fails) and keep the same exit codes. Without `--yes`, apply still only shows what it would do.
- ND-215 When the installer's choices file says the alerts part was chosen and the person has not saved a choice of places for alerts, alerts shall go to the console, the file and the screen. A settings file from an earlier version that lists only the console counts as no choice; a list with anything else in it is the person's own choice, and so is a list left empty on purpose.
- ND-216 With no choices file, or one that says the alerts part was not chosen, alerts shall go only to the places the person saved, and to the console when none were saved. The base install saves no alert file and shows no alerts.
- ND-217 When the choices file says the alerts part was chosen, the setup helper shall ask one question, "Keep alerts on the screen and in a file?", where Enter means yes and `n` means no, and save the answer as the person's choice of places. When the file says it was not chosen, setup shall not ask. With no choices file, setup shall ask the earlier question.
- ND-218 The installer's alerts line shall say in one plain sentence that alerts are kept in a file and shown on the screen, and that setup can turn them off.
- ND-219 `config alerts-file on` and `off` shall start from where alerts really go, so with the alerts part installed and nothing saved, switching the file off keeps the console and the screen.
- ND-220 The check shall also list, in `undos`, each fix it can put back: its plain undo title, the setting now (what the fix left), what Undo would put back, and whether Windows asks for administrator rights. A fix is listed only when its saved old value exists in the results folder, the setting today still is exactly what the fix left (for the proxy: off, with the same server text), and putting it back would change something. A setting changed by hand since the fix is not listed. Making the list changes nothing: no setting, and not the saved values file either; a stale saved value stays on file and is replaced by the next fix. With no results folder known, the list is empty.
- ND-221 `fix undo NAME` shall refuse, with a plain reason and a non-zero exit code, when the setting is no longer what the fix left (the reason says what the setting is now and what the fix left, naming the proxy server when that is what differs), and shall then change nothing, ask for no administrator rights and log nothing; so a press on an old card can never put back a stale value.
- ND-222 A fix shall never be in both `fixes` and `undos` in one check: when it is offered as a fix, it is not listed as an undo.
- ND-223 The check and `fix undo` shall use the same results folder, so every undo the check lists can be done by `fix undo NAME` on that machine.
- ND-224 `fix apply proxy --yes` shall refuse, with a plain reason and a non-zero exit code, when the web proxy is already off, and shall then save, change and log nothing, so a second apply never replaces the only saved old value.
- ND-225 The check shall never list power saving in `undos`, even when a power saving value is saved, because the power saving fix is never offered.
- ND-226 A device shall count as known when its hardware address is on the tool's own list (`known-devices.txt`) or in the file named by the `known-from` setting. That file is a JSON object whose keys are hardware addresses (dashes or colons, any case), as another program might store the devices it trusts; a leading byte order mark is allowed. With no setting, or no such file, only the tool's own list counts, as before. The check and the alerts watcher shall use the same joined list.
- ND-227 While `watch` runs, it shall read both lists again at every full check, so a device marked known after it started stops being warned about without a restart. When the `known-from` file exists but cannot be read or understood (for example while it is being written), the watcher shall keep the last good list, say so once in plain words, and never fall back to an empty list.
- ND-228 The watcher shall not warn that the router (the adapter's gateway) is an unknown device, as it already does not for this computer.
- ND-229 `netdoctor config known-from PATH` shall save the path, `config known-from off` shall clear it, and `config show` shall print it. The program shall contain no built-in path to any person's folder.
- ND-230 When the connection in use is Wi-Fi, the Wi-Fi is up, and Windows refuses the Wi-Fi details (`netsh` fails and names location permission), the check shall say so in plain words in `wifi_hidden` (a headline and a reason) and in the plain output; it shall not say so on a wired connection, when the Wi-Fi is down, or when the details were read. The words shall state the fact only: they shall never tell the user to turn on Location or link to a setting, and the tool shall never change that setting. A Wi-Fi diagnosis shall not be hidden silently: with the details hidden and a slow router, the finding shall say a weak signal cannot be ruled out.
- ND-231 The check shall send one plain web request to the address the system itself uses to test for a sign-in page (a fixed address for each of Windows, Mac and Linux), and when the answer is a redirect or a page that is not the expected one, it shall set `sign_in` (a headline "This Wi-Fi needs you to sign in through a web browser." and one plain reason) and the finding shall name the sign-in page, not the router or the provider, with "Open a web browser and look for the sign-in page." as the first thing to check. It shall store no cookie, send nothing about the person, use no outside address beyond those system ones, and say nothing when the request cannot be made or the expected answer comes back. Read-only on every system.
- ND-232 The check shall compare the computer's clock with the Date header of an answer it already gets (the sign-in request of ND-231), and when they differ by more than 5 minutes it shall set `clock` (a headline that says the clock is wrong by about that many minutes and a reason that a wrong clock makes websites and sign-ins fail while the network is fine). It shall never change the clock, and say nothing when there is no answer, no Date header or the difference is 5 minutes or less.
- ND-233 The Wi-Fi advice shall say the signal is weak when it is at or below -75 dBm (50 percent on Windows' scale), and shall say the link is slow, with the speed and "Move closer to the router, or try the 5 GHz band.", when the Wi-Fi link speed that was read is under 20 megabits. A signal or speed that was not read (hidden by Windows or zero) shall never count as weak or slow, and no advice shall tell the person to turn on Location.
- ND-234 When the measured download is under one fifth of the measured upload (upload at least 20 megabits), or under one fifth of the download of the last weekly check, the check shall run one more speed test, with Cloudflare only and never with Ookla, once per check, never in quick mode, never inside a speed hold, never changing the hold, and set `speed_recheck` with both pairs of numbers, the tool of the second test, and a headline that says the first number looks wrong and what the second test gave (or that the second test could not finish). The plan comparison in the finding shall use the higher of the two download numbers, so one odd number is never shown as the answer.
- ND-235 There shall be a fix named `public-dns` that, on Windows, saves the current name servers of the adapter in use (or that they were automatic), sets the adapter in use to Cloudflare's 1.1.1.1 and 1.0.0.1, and clears the saved web addresses. It shall be offered only when web names fail to resolve while the internet answers, only with the person's yes each time, shall say in its text that all website lookups then go to a third party, shall ask Windows for administrator permission, shall read the servers back afterwards and report a refusal or a failed change as failed, and `fix undo public-dns` shall put back exactly the saved servers and refuse when they changed since (the same rule as the proxy fix). Mac and Linux: ND-304 (amended 2026-11-20).
- ND-236 There shall be a fix named `renew-address` that, on Windows, asks the router for a new address for the adapter in use. It shall be offered only when that adapter is up and has no usable address (none, or one starting 169.254), so nothing in use is lost, with the person's yes each time and Windows' administrator permission, and it shall read the address back afterwards and report a failure as failed. It has no undo (nothing is changed that could be put back), and `fix list` and the check shall say so. Mac and Linux: ND-305 (amended 2026-11-20).
- ND-237 There shall be a fix named `reset-adapter` that, on Windows, switches the adapter in use off and on. It shall be offered only when the connection is already dead (no internet answer and no router answer), so nothing in use is lost, with the person's yes each time and Windows' administrator permission, and it shall report a failure as failed. It has no undo, and the check shall say so. Mac and Linux: ND-306 (amended 2026-11-20).
- ND-238 `public-dns`, `renew-address` and `reset-adapter` shall be refused on any system where the tool they need is missing (ND-307), shall never be offered on a connection that works, and shall appear in `fix list`, `fix apply NAME --yes --json` and `fix undo NAME --json` like the existing fixes, with `needs_admin` true. (Amended 2026-11-20: they were refused on all Mac and Linux computers; ND-304 to ND-306 bring them there.)
- ND-239 On Wi-Fi that is joined (the adapter is up) with no usable address from the router, the finding shall say "The Wi-Fi is connected but got no address from the router." with a first check of "Restart the router, or press the button that asks it for a new address.", and never say the cable has no link.
- ND-240 The driver date shall be read and the driver's age in days shall appear when the date can be read; when it cannot be read, nothing shall be said about the driver's age.
- ND-241 The VPN line shall say "No VPN program is running on this computer. A VPN on your router cannot be seen from here, and it can change the speed and the provider shown." A VPN note comes only from a change in where the internet leaves from (ND-248).
- ND-242 The Wi-Fi reader shall work on a Windows set to another language: it shall find the signal, band, channel and link speed by their units and shape and not only by English words, and shall treat the Location refusal as hidden when `netsh` fails and the Location consent value in the registry (read-only, machine and user) says denied, with the neutral words "Windows did not share the Wi-Fi details." when only the failure tells it so.
- ND-243 After any step run with administrator permission, the program shall check by reading the result back, and shall report failure, not success, when Windows refused or the result is not there.
- ND-244 At the press of a button the program shall read the situation again and shall refuse `reset-adapter` when the router or the internet answers now, and `renew-address` when a usable address is there now, with a plain note that the trouble is gone and nothing was changed; when the situation cannot be read the two fixes are refused with a plain note. `public-dns` shall set only the adapter in use (the one carrying the connection), shall save only that adapter's servers, and shall not be offered behind a sign-in page. The words each fix shows for the setting now shall be read from the computer, never fixed text.

- ND-246 The nearby-networks channel list shall be read on a Windows set to another language: a block starts at a BSSID line, and its channel is the first whole number after the radio type line (a value starting with 802.11); the English word Channel still counts; one entry on the user's own channel is dropped.
- ND-247 On a Mac with no default route, a Wi-Fi port that is joined (status active) with no usable IPv4 address (none, or a self-made 169.254 one) and no global IPv6 address shall give the same finding as ND-239; the read shall run only when no default route was found.
- ND-248 The check shall say where the internet leaves from in plain words, from one small extra request, made on each check that is online, to the speed test's own host, which answers with a country code and nothing about the person, and shall remember it. - ND-249 The public source tree shall hold no private words, no personal data, no local user path, no personal address, no backup file and no working-note file, and the lines that name the one other program that uses the tool shall stay at the few the public page already had. - ND-296 On GitHub's clean Windows, Mac and Linux machines, a headless browser shall take pictures of the page after its check, the install page's choices and its finish screen (Mac and Linux), at one fixed size of 1280 by 800 pixels, and upload them as run artifacts; looking at them, the same parts shall show in the same order on all three, with differences only in fonts and in the numbers the machine reads.
- ND-297 On GitHub's clean Linux and Mac machines, a second press of the launcher's command shall retire the first page: the first server shall answer the old page's heartbeat with 410 and quit, and `open-page.json` shall name the new port.
- ND-298 On a Mac, the check shall read the person's 12 or 24 hour setting from the global `AppleICUForce24HourTime` value (1 means 24-hour, 0 means 12-hour) and send `clock_24h`; a missing or other value means not known, and the page then uses the browser's own format. The read changes nothing.
- ND-299 On Linux, the check shall read the desktop's clock format from `gsettings get org.gnome.desktop.interface clock-format` ('24h' or '12h') and send `clock_24h`; a missing tool, an error or any other answer means not known, and the page then uses the browser's own format. The read changes nothing.
- ND-300 When no browser starts, on a Mac a dialog made with `osascript` shall show the address with an OK button, and on Linux a box from `zenity`, or else `kdialog`, shall show it; the program shall stop when the person presses OK; when no such program is there, the address shall be printed. The address shall be given as an argument, never written into script text.

### Ookla's tool

- ND-301 The install page shall offer Ookla's tool on its own step, as the Windows installer does (ND-210): unticked at first, with links to Ookla's license and terms, a second tick for the person's own acceptance of the license required, and never in a silent install; its words shall be the Windows Ookla page's words, except that it shall not call the tool a "command-line tool" (ND-280 wins on Mac and Linux; the Windows page stays as it is).
- ND-302 After both ticks, the install shall fetch Ookla's file for that system only from `install.speedtest.net` over https (the Mac file on a Mac; on Linux the file for the computer's chip, x86_64, aarch64 or armhf), check it against the fixed SHA-256 the program holds for that file, unpack it into the `ookla` folder beside the program only when it matches, give the license switches to the tool once and only then, and set `ookla` true in `choices.json` only when the tool then ran; a file that does not match shall be deleted, the install shall go on without it, and the finish screen shall say in plain words that the speed tool was not added.

- ND-304 On a Mac (`networksetup -setdnsservers` for the service in use, where "Empty" means automatic) and on Linux (`nmcli` for the connection in use), the `public-dns` fix shall do what ND-235 and ND-244 say for Windows: the same offer conditions, the saved servers, the read-back and the exact undo.
- ND-305 On a Mac (`ipconfig set` with DHCP for the adapter in use) and on Linux (`nmcli device reapply` for the adapter in use), the `renew-address` fix shall do what ND-236 and ND-244 say for Windows.
- ND-306 On a Mac (`networksetup -setnetworkserviceenabled` off then on for the service in use) and on Linux (`nmcli device disconnect` then `connect` for the adapter in use), the `reset-adapter` fix shall do what ND-237, ND-244 and ND-245 say for Windows.
- ND-307 On Mac and Linux, a fix whose system tool is missing shall be refused in plain words and change nothing, and shall be neither in `fixes` nor in `fix_offers`; power saving shall stay refused on all three systems; administrator permission shall be asked only at the moment of approval (ND-94); and the tests of these fixes shall run only pretend commands, never a real network change.

### Rules and proof

- ND-308 The Mac and Linux setup files shall be offered only privately: this job shall make no change to the public showcase repository and publish no download.
- ND-309 On GitHub's clean Linux machine, and then its clean Mac machine, the setup file built in that run shall be installed fresh with `install --silent --parts=scheduled,proactive`, and every file, icon and job of ND-269 to ND-275 and ND-282 to ND-286 for that system shall then exist.
- ND-310 On those machines, the installed weekly job shall be run once on demand through the system that holds it (`launchctl kickstart`, `systemctl --user start`, or the marked crontab line's own command), and one row shall be added to `weekly.csv`.
- ND-311 On those machines, the installed alerts helper shall be started as its job starts it, made to raise one alert, and one line shall be added to the alerts file; the screen alert attempt (shown, or the plain log line of ND-288) shall be recorded in the run log.
- ND-312 On those machines, `uninstall --silent --keep-results`, then after a fresh install a plain `uninstall --silent`, and after another the old `uninstall --silent --delete-results`, shall each leave no process of this program running, no icon, launcher, LaunchAgent, user unit, marked crontab line or autostart entry, with the results folder kept after the first and gone after the old switch (and, on Linux, after the plain `uninstall --silent` that ends the crontab pass); before the plain `uninstall --silent` in the sequence, undo notes are planted that cannot be put back without changing anything (on a Mac a web proxy note, whose undo may need the Mac password; on Linux a notes file that cannot be read), and that removal shall exit 1, say the change could not be put back, and leave the results folder holding only the undo notes (ND-316).
- ND-313 The Mac and Linux proof shall run in their own workflows, `.github/workflows/parity-linux.yml` and `.github/workflows/parity-mac.yml`, started only by hand or by a push to one work branch (`parity-work` for Linux, `parity-work-mac` for Mac, so the Mac run never starts by accident); the Mac workflow shall have a time limit of 30 minutes or less, shall be run only after the Linux one has passed, and the minutes it used shall be reported.
- ND-314 Every text a person sees on the install page, its finish screen, the uninstall page, the Mac open page, the dialogs and the screen alerts shall read at grade 8 or lower (ND-05), and the Mac and Linux texts shall be the same except for the system's folder names, menu names and removal route.
- ND-315 `install` and `uninstall` shall send nothing off the computer, except the fetch of Ookla's file from `install.speedtest.net` after both ticks (ND-302).
- ND-316 Before removal deletes anything (the program, the choices file, the results folder), on Windows, Mac and Linux, it shall put back every fix still recorded as applied in the undo notes (`fix-saved.json` in the results folder), one by one, with the program's own undo, the same one as `fix undo NAME` (ND-223); with nothing recorded it shall touch no setting at all, and a note file that cannot be read counts as a fix not put back. It shall do so with `--keep-results` and `/KEEPRESULTS` too, because the program that made the changes goes away either way; a fix not put back then stays recorded with the kept results. A recorded fix whose setting the person changed by hand after the fix counts as settled, not as a fault, but only when that setting was read without any error and seen changed on the very adapter or setting the fix changed (for the name servers: every adapter the fix changed is still listed, on Linux with the same NetworkManager connection, and its servers differ from what the fix set), and only when the note's recorded account (on Windows the user name and SID, on a Mac and Linux the user name and number, written beside each note when the fix is applied) is the account the removal runs as. An adapter that is gone from the list (offline, or another adapter or connection in use), a setting that cannot be read or any read error (a read is never taken as "off" or "not set" when it failed), a note written by another account, or an older note with no account is a real failure, its note kept, with the reason said in plain words. Settled means: the person's own setting wins, removal changes nothing there, deletes that fix's note, keeps nothing for it, and says in plain words that the change was left as you set it; the exit code stays 0 when nothing else went wrong. Only removal settles it: `fix undo NAME` still refuses such a fix as before. When every recorded fix is put back or settled, removal goes on as ND-118 and ND-291 say. When any is not put back (the computer refused or the undo failed, it needs administrator rights, or the notes cannot be read), removal shall still take away the program, its icons and its jobs, but shall keep the results folder holding only the undo notes (`fix-saved.json`, `fix-log.txt`, `fix-enabled-here.txt` and, on Windows, `fix-not-undone.txt`), delete every other file in it (in a removal with both, only the notes of the fixes not put back stay), and say in plain words which change could not be put back, that its notes are kept in that folder, and what the person can do next: install Network Doctor again and put the change back with its undo (the guide's "Fix a problem" part says how), or change the setting back by hand. On Mac and Linux removal never asks for administrator rights (ND-274), so a recorded fix whose tool may ask for them there is not tried and counts as not put back, with the reason that it needs administrator rights, which removal never asks for: on a Mac that is every fix with an undo (the web proxy and the name servers), on Linux the name servers; the Linux web proxy is the person's own setting and is put back. Power saving is never changed on Mac or Linux, so it is never recorded there. `uninstall --silent` then exits 1 and prints those plain lines. On Windows the uninstaller shall run the installed program's `fix undo-all` once, after the person confirms and before the tasks, the program or the results are removed, naming the results folder with `--dir` (so a `NETDOCTOR_DIR` set for the whole computer cannot point it at other notes), adding `--kept` with `/KEEPRESULTS` (so the note says the results are kept, not deleted), and deleting any `fix-not-undone.txt` from an earlier removal first; when it reports a fault, or cannot start while notes exist, the uninstaller keeps the undo notes as above, writes the plain lines to its log and, unless the removal is silent, shows them once in a message with only an OK button. A settled change is written to `fix-not-undone.txt` too, and the uninstaller shows it the same way while the removal goes on as normal. With no notes, or notes with nothing recorded (`{}`), it goes on as now even if the program cannot start. Inno Setup gives the uninstaller no way to set its own exit code, so on Windows the kept `fix-not-undone.txt` and the log are the record. Removal puts back a fix still applied, so no change made by the program outlives it unseen. A setting the person changed by hand after the fix is settled, not a fault.
